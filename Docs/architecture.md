# SP.Engine Architecture Specification

SP.Engine은 .NET 8 인프라를 기반으로 구축된 고성능 실시간 멀티플레이어 게임 서버 엔진입니다. 본 프로젝트는 상용 엔터프라이즈 솔루션이 아닌, 고도의 로우레벨 최적화와 동시성 제어 기술을 증명하기 위해 설계된 **상용 서비스 수준의 아키텍처를 지향하는 포트폴리오/토이 프로젝트**입니다. 

서버 가용성과 처리량(Throughput)을 제한하는 두 가지 최대 요인인 **GC(Garbage Collection) 스파이크**와 **스레드 간 락 경합(Lock Contention)**을 프레임워크 레벨에서 원천 차단하는 것을 최우선 사상으로 구현되었습니다.

본 문서는 최하단 버퍼 관리부터 최상단 분산 서버 커넥터 레이어까지 아키텍처 구조와 유기적 패킷 흐름, 그리고 동시성 통제 정책을 정밀 정의합니다.

---

## 1. 전반적 스레드 모델 및 컨텍스트 격리 (Threading & Execution Model)

SP.Engine은 무분별한 멀티스레드 레이스 컨디션을 배제하고 컨텍스트 스위칭 비용을 최소화하기 위해 입출력(I/O) 스레드와 비즈니스 로직 스레드를 물리적으로 분리하는 아키텍처를 채택합니다.

```
[ Clients ] ──► (TCP / UDP Hybrid Transport)
                       │
                       ▼
[ 네트워크 입출력 레이어 ] ──► `SocketServer` & `Tcp/UdpNetworkSession`
                       │ * Pinned Buffer 풀링 및 IOCP 비동기 입출력 가속
                       ▼
[ 메시지 런타임 레이어 ]   ──► `ReceiveSequenceReorderer` (L7 시퀀스 정렬 & 중복 검증)
                       │ * 네트워크 스레드 컨텍스트 (`EngineBase.ExecuteCommand`)
                       ▼
[ 비즈니스 로직 레이어 ]   ──► `ThreadFiber` Pool Sharding ($PeerId \& \text{Mask}$)
                         * 락 프리 비즈니스 로직 실행 및 가상 스레드 틱 제어
```

### 가상 스레드 기반 로직 샤딩 (Fiber Pool)
* **독점 스레드 바인딩:** 유저 객체(`Peer`)들은 코어 수 기반의 비트 마스킹 샤딩 연산을 통해 전용 `ThreadFiber` 스케줄러 내부의 무락 큐(`BatchQueue`)에 영구적으로 바인딩됩니다.
* **Lock-free 콘텐츠 개발:** 특정 파이버 큐에 진입한 작업은 내부 스레드가 독점하여 순차 처리하므로, 상위 비즈니스 로직(Room, 대전, 매치메이킹 등) 전반에서 스레드 동기화 락(`lock`)을 완전히 배제하고 단일 스레드와 동일한 무락 환경을 제공합니다.
* **일괄 데큐 가속 (Batch Dequeue):** 작업을 소비할 때는 1개씩 꺼내지 않고, 아키텍처 임계치(`_maxBatchSize`) 범위 내에서 Span 구조를 활용해 단 한 번에 일괄 데큐(`DequeueBatch`)하여 실행 컨텍스트 락 경쟁을 무력화합니다.

## 2. 하이브리드 트랜스포트 레이어 (Hybrid Transport Layer)

데이터 성격에 따라 전송 파이프라인의 신뢰성과 반응성을 극대화하기 위해 물리 프로토콜을 이원화하여 제어합니다.

### A. TCP 채널 (Reliable Channel)
* 인증, 로비, 결제, 아이템 조작 등 데이터의 무결성과 절대적 전송 신뢰성이 보장되어야 하는 비즈니스 패킷을 전담합니다.
* 바이트 스트림 수신은 최하단 전용 버퍼인 `ReadWriteBuffer`를 통해 제어됩니다.

### B. UDP 채널 (Unreliable / Fast Channel)
* 실시간 레이텐시(Latency)가 최우선인 이동 동기화, 시야 동기화, 타격 액션 패킷을 전담합니다.
* **가변 MTU 및 조립 (`FragmentAssembler`):** 인터넷 망 환경에 따라 가변 MTU 크기를 동적으로 타협하고, 이를 초과하여 파편화된 UDP 패킷들을 커널 버퍼링 오버헤드 없이 고속 스트림으로 단편화 조립합니다. 개별 `FragmentContext` 단위의 국소 락 제어를 채택하여 멀티스레드 수신 환경에서의 컨텐션을 정교하게 분산시켰습니다.

## 3. 세션 수명 주기 및 폴트 톨러런스 (Session & Resumption)

무선 네트워크 전환(Wi-Fi ↔ LTE/5G) 및 순간 단선 스파이크에 대응하기 위해 상용 엔진에 준하는 방어 메커니즘을 내장하고 있습니다.

### 세션 복구 메커니즘 (Session Resumption)
* **물리/논리 레이어 분리:** 물리 소켓 연결(`Session`)과 논리적 유저 실체(`Peer`)의 생명주기를 구조적으로 분리 제어합니다.
* **송신 윈도우 동결:** 하위 소켓 단선 이벤트 감지 시 `Peer`와 송신 슬라이딩 윈도우의 미확인(In-flight) 메시지 트래커를 즉시 파괴하지 않고 `PendingReconnect` 상태로 동결 유지합니다. 
* **정밀 재전송:** 제한 시간 내에 새 소켓으로 클라이언트가 재인증 진입 시, 수신단 시퀀스 넘버부터 윈도우 내 미확인 패킷들을 정밀 재전송하여 단절 없는 게임 플레이 연속성을 보장합니다.

## 4. 고성능 메모리 매니지먼트 (End-to-End Zero-allocation)

C# 실시간 서버 성능 최적화의 최대 취약점인 JIT 컴파일러 런타임의 GC 압박을 인프라 레벨에서 은닉 및 제거했습니다. Zero-allocation 지향 사상을 구체적으로 구현한 핵심 요소는 다음과 같습니다.

* **Pinned Buffer 기반 IOCP 가속:** 소켓 입출력 시 `GC.AllocateArray<byte>(..., pinned: true)`를 활용한 고정형 버퍼 풀(`ExpandablePool`)을 연동하여 OS 커널과 런타임 간 메모리 복사 및 핀 고정 오버헤드를 원천 배제합니다.
* **비트 마스크 링 버퍼 (`ReadWriteBuffer` / `SendRingBuffer`):** 2의 거듭제곱 크기 제어와 비트 연산 마스크를 결합해 모듈러(`%`) 연산 비용을 지우고, 송신 플래그 제어를 통한 단일 스레드 일괄 발송(Serialized Flush) 구조로 컨텍스트 스위칭을 최하단으로 낮춥니다.
* **2단계 경합 제로 오브젝트 풀ing:** 패킷 직렬화/역직렬화 및 작업 위임 전 과정에 `[ThreadStatic]` 로컬 스택 캐시(최대 512개)와 글로벌 Concurrent 큐를 연동한 하이브리드 풀링(`ProtocolPool`, `WorkJobPool`)을 주입하여 스레드 간 락 경쟁 없는 가속 렌트를 구현했습니다.

## 5. 세부 컴포넌트 데이터 패스 및 무결성 제어 정책

### A. 송신(Outbound) 파이프라인: 자율 확장 직렬화
* **명세 의존성 탈피:** 패킷을 송신할 때 프로토콜 정책 구조체의 `MaxPayloadLength` 설정을 완벽하게 무시하고 배제합니다.
* **가변 리사이저 가동:** 직렬화 단계(`MessageBase.Serialize`)에서 코어 레이어의 `BufferResizer`를 `NetWriter` 생성자 단에 주입하여, 초기 256바이트 수준의 매우 작은 버퍼 풀 공간에서 시작합니다. 직렬화 도중 용량이 부족하면 예외나 무거운 루프 없이 `CheckAndGrow` 분기를 통해 네이티브 고속 메모리 복사(`CopyTo`)로 버퍼 주소를 자율적으로 확장해 나갑니다.
* **정밀 렌트:** 최종 직렬화가 완료된 알짜배기 물리 크기(`WrittenCount`)를 기반으로 암호화(`AesGcmEncryptor`) 및 압축(`Lz4Compressor`) 마진을 정확하게 역산하여 `BufferOwnerPool`에서 딱 한 번만 정밀하게 렌트하므로 버퍼 풀의 자원 회전 속도가 극대화됩니다.

### B. 수신(Inbound) 파이프라인: 글로벌 설정 일괄 제어
* **의존성 결합 해제:** 최하단 TCP 스트림 버퍼인 `ReadWriteBuffer`가 상위 도메인 명세인 프로토콜별 개별 임계치 구조체를 참조하는 설계 결함을 걷어내고, 서버 설정의 전역 상한선(`Config.Network.MaxPayloadLength`) 단일 지점으로 일괄 통제합니다.
* **네트워크 컨텍스트 정렬 무결성:** 소켓 스트림 데이터 수신(`EngineBase.ExecuteCommand`)은 멀티스레드(IOCP Worker Thread) 컨텍스트에서 인입되므로, `ReceiveSequenceReorderer` 내부에서 `ReaderWriterLockSlim`을 통해 멀티스레드 경합을 완벽하게 방어하며 L7 시퀀스 넘버 정렬을 안전하게 수행합니다. 정상 상태 시 Write 락의 보유 시간이 극히 짧고, 모니터링 시 Read 락 분기가 타므로 소켓 스레드들을 블로킹하지 않습니다. 변조되거나 설정 한도를 넘어서는 해킹 패킷은 즉시 `MessageReadResult.CorruptedPayload` 상태 분기로 검출되어 락 구역 밖에서 안전하게 세션을 강제 단선(`Close`) 처리합니다.

### C. 락 분산 및 파이버 진입 무결성
* **`ReliableSendWindow` 락 최소화:** 멀티스레드 환경에서 `Interlocked.Increment`를 통해 고유 시퀀스 번호(`seq`)를 락 밖에서 안전하게 선발급합니다. 슬롯 주입 시 비트 마스킹을 통해 배열 주소가 수학적으로 완벽히 격리되므로 데이터 무결성이 유지되며, `lock (_lock)` 구역의 임계 점유 시간을 최소화합니다.
* **파이버 큐 유실 차단 (Infinite Spin Enqueue):** 복수의 소켓 입출력 스레드가 파이버 큐에 진입할 때 일시적인 포인터 경쟁으로 발생하는 `Contention` 상태에 대해, 하드코딩된 드롭 제한을 철폐하고 `.NET 표준 SpinWait` 지수 백오프 기반의 무제한 스핀 구조체 파이프라인으로 전환하여 패킷 유실을 0%로 통제합니다. 물리적으로 완전히 고갈된 `Full` 상태에 대해서는 파이버 스레드의 비즈니스 처리를 위해 커널 컨텍스트를 강제 양보(`Thread.Sleep(1)`)하는 방어선을 구축했습니다.

## 6. 프로토콜 타입 바인딩 및 직렬화 엔진 (`SP.Core.Serialization`)

### 리플렉션 비용 제로화 및 정적 메타데이터 구조
* **`ProtocolMetadata<T>`:** 제네릭 정적 생성자를 활용하여 해당 프로토콜 구조체/클래스가 최초 로드되는 시점에 단 1회만 리플렉션을 수행하여 고유 ID와 채널 정보를 스태틱 전역 주소에 박제합니다. 런타임 실행 중 어트리뷰트 조회 비용은 완전한 0%입니다.
* **상속 제약을 통한 layout 무결성:** 프로토콜 자체의 상속 구조를 아키텍처 레벨에서 강력히 제한합니다. 이는 C#의 `GetMembers`가 상속 계층의 모든 멤버를 수집할 때 발생하는 바이트 직렬화의 레이아웃 순서 뒤틀림을 차단하고, 결정론적 무결성(With `MemberAttribute.Order`) 및 속성 ID 충돌을 차단하기 위함입니다. 2차 가공 필요 시 조합(Composition) 패턴을 지향합니다.
* **`NetSerializerBuilder` 고속 동적 컴파일:** 타입 정보를 런타임 중에 사용하기 위한 `IMemberAccessor` 인터페이스의 일반 호출 로직(`GetValue`/`SetValue`)은 툴이나 범용 컴포넌트 구역으로 완전히 격리 은닉했습니다. 네트워크 실제 직렬화 코어 엔진은 값 타입(Primitive, Struct, Enum) 인입 시 `object` 캐싱 단계를 원천 우회하며, JIT 컴파일러 수준에서 비박싱형 제네릭 전용 다이렉트 대입 연산 함수로 완전 동적 IL 컴파일을 완결 지어 GC 발동 인자를 제거했습니다.

## 7. 분산 환경 확장을 위한 S2S 커넥터 인프라

SP.Engine은 단일 물리 서버 스펙에 종속되지 않고, 백엔드 분산 아키텍처(Game ↔ Rank, DB Proxy, Matchmaking)로 유연하게 스케일아웃할 수 있는 고성능 커넥터 인프라를 탑재하고 있습니다.

* **대칭형 통신 스택:** 클라이언트용 소켓 엔진 레이어인 `NetPeerBase`를 백엔드 커넥터가 상속/래핑하여 대칭적으로 재사용합니다. 분산 서버 간 통신 시에도 자체 고속 암호화(AES-GCM), LZ4 가변 압축, Zero-allocation 커맨드 시스템 성능 강점을 공유합니다.
* **커넥터별 독립 Fiber 격리:** 각각의 아웃바운드 백엔드 연결 노드 채널마다 독점적인 `ConnectorFiber`와 전용 `IFiber` 컨텍스트를 배정합니다. 특정 백엔드 노드(예: 글로벌 레디스나 특정 DB 노드)의 일시적인 덤프 정체나 네트워크 초킹 현상이 유발되더라도, 메인 게임 루프를 지탱하는 비즈니스 로직 샤드 스레드 풀에는 단 1ns의 간섭(Interference)이나 성능 부하 전하도 주지 않도록 완벽하게 물리 차단 격리되어 구동됩니다.
* **원자적 재접속 타이머 누수 제어:** 물리 단선 시 백그라운드 재접속 타이머 등록 구역에서 멀티스레드 이벤트 연속 유발에 따른 중복 할당 및 누수를 방지하기 위해, 기존 타이머를 확실히 폐기하고 `Interlocked.Exchange`와 인프라 스케줄러 타이머를 연동하여 안전하게 가동 세션을 자율 실시간 복구합니다.
